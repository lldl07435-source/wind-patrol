# 多用户使用与部署说明

维护版本：1.1.1。记录日期：2026-10-02。现有申请版本及历史开发完成日期保留在原材料中，本次维护按实际发生日期记录。

## 本机开始使用

1. 使用现有启动脚本打开网页。首次启动自动创建账户数据库并应用迁移。
2. 在注册页创建自己的用户名和密码。密码至少12个字符。注册后自动登录。
3. 完成一次运行，再点右上角“我的数据”。按名称、编号或日期查询，下载任务结果或整个个人工作区。
4. 用另一个账户登录，看到的是该账户自己的记录。两个项目各自管理账户；没有合并登录。

本机 LD-Flex 默认使用项目内 `data/`；巡检 PyCharm 项目使用原来的 `运行结果/`，源码发布包解压后使用代码目录内 `data/`。启动时输出实际路径。账户库保存在数据目录的 `accounts.sqlite3`，个人业务数据保存在 `users/<工作区编号>/`。工作区编号由服务器生成，接口不接收客户端指定的用户编号或磁盘路径。已有单用户数据原目录继续保留，不会由第一个注册用户自动取得。

## 将已有记录交给自己的账户

先在网页注册账户，退出并停止服务。在项目代码目录打开终端，使用项目解释器运行：

```text
python manage.py import_legacy 你的用户名
```

只能导入到空账户。工具复制旧任务库、工程库或运行目录，生成真实时间和文件摘要；原文件保留。再次导入会拒绝，避免覆盖已有记录。失败时保留暂存资料便于核对。

LD-Flex 实物操作还需要在本机运行 `python manage.py grant_operator 你的用户名`，再刷新网页。该命令不会启动设备。连接必须收到控制板协议应答，之后仍须人工清空确认。蓝牙 COM 口通常不是 USB-TTL 控制板。部署后的在线站点提供仿真、实验和个人记录，实物串口操作在设备电脑完成。

## 数据库与恢复

停服后运行 `python manage.py backup_workspace 备份保存目录`。备份含账户数据库、个人工作区 ZIP、文件摘要和本机密钥。将备份放在独立磁盘；不要上传公开仓库。

恢复时先停止服务，把当前数据目录完整复制为另一个备份，核对 manifest.json 的 SHA-256。将 accounts.sqlite3 放回数据根目录，各工作区 ZIP 解压至 users/对应编号。工作区 ZIP 的编号必须与账户库中的对应关系一致。本机 `.portal-secret` 一并恢复。生产环境的 LD_SECRET_KEY 从服务器密钥设置恢复。然后运行 migrate，启动，核对登录和任务数量。保留原目录直到核对完成。

普通用户可在“我的数据”修改密码；其他会话随即失效。忘记密码时由服务器管理员在代码目录运行 `python manage.py changepassword 用户名`。当前没有邮件验证或邮件找回流程。

## Linux 服务器部署

现有 Python 仿真及 LD-Flex 的 C 动态库需要服务器运行。Sites 的默认站点部署要求 Cloudflare Workers 兼容产物；此版本没有改写为 Workers 后端。Docker 和 Render 配置已准备，接通服务器后发布。不要只把静态 HTML 上传到 GitHub Pages，登录和数据库功能需要后端。

每个项目单独部署一个服务、一个持久数据卷，使用单个 Gunicorn worker、6个请求线程。当前内存控制会话不支持多个 worker 或副本。每站点最多两个同时计算任务，默认每账户100 MB、500条运行记录；可通过 LD_WORKSPACE_MB、LD_MAX_RECORDS 修改。在线 LD-Flex 单次对照实验最多10组、每组40件。更大规模并发需另建任务队列并统一业务存储。

```text
python prepare_env.py
docker compose up -d --build
docker compose logs --tail 80
```

prepare_env.py 要求输入实际域名并生成本地 .env 随机密钥。检查 APP_PORT：LD-Flex=8876，多风巡检=8765。服务只把端口映射到服务器回环地址。使用 docs/Caddyfile.example 配置 Caddy，两个域名分别反向代理两个端口，Caddy 管理 HTTPS。域名 A/AAAA 记录应与服务器匹配。Caddy 配置会覆盖写入 X-Real-IP，配合 LD_CLIENT_IP_HEADER=X-Real-IP 按实际访问者限流。只有该头由可信代理覆盖时才配置它；Render 的客户端地址头应按实际代理核对，默认采用连接来源作限流分组。LD_TRUST_PROXY 只用于该可信代理；不要把应用端口直接开放公网，否则客户端可伪造转发头。

Render 可导入 render.yaml。设置至少50字符的 LD_SECRET_KEY、准确的 LD_ALLOWED_HOSTS，以及带 https:// 的 LD_CSRF_ORIGINS。允许域名须包含服务实际地址和127.0.0.1，不能用星号。挂载 /var/data 持久磁盘。容器入口先整理该数据卷的属主，再降到 uid/gid 10001 运行服务，不跟随符号链接修改其他位置。不可用其他挂载路径替代 /var/data。Render 的普通文件系统会在部署或重启后丢失变动；持久磁盘属于付费服务能力，费用以账户实际报价为准。此方案也可在已有 Linux 服务器上部署两个项目，共用 Caddy。

上线核对：healthz 返回200；HTTPS注册登录成功；两账户记录互不相见；服务重启后登录和记录可读；任务及个人工作区ZIP可下载。网站尚未公开发布时，不要把本机地址当成公网链接。
